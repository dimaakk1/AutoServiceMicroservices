# Ноутбуки для порівняння моделей

- `repair_duration.ipynb`: Ridge, випадковий ліс, дерево рішень, градієнтний бустинг і медіана. Вибір за MAE на валідації. Додатково: RMSE, R², графіки похибок і фактичної тривалості проти прогнозованої.
- `delay_risk.ipynb`: логістична регресія, випадковий ліс, дерево рішень, градієнтний бустинг і базова частка затримок. Вибір за Brier score на валідації. Додатково: accuracy, precision, recall, F1, ROC AUC, матриця помилок і графік калібрування.

Для дерева перевіряються 12 конфігурацій (глибина й мінімальна кількість прикладів у листку), для бустингу — 36 (також кількість дерев і швидкість навчання). Спочатку ноутбуки показують найкращі параметри кожної моделі, потім усі перевірені конфігурації. Тестова вибірка не використовується для підбору параметрів.

Обидва ноутбуки також показують результати на тесті окремо за кількістю послуг. Якщо в групі немає замовлень, метрика для неї не обчислюється.

## Запуск у Windows

З кореня репозиторію створи окреме середовище на Python 3.11 або 3.12:

```powershell
python -m venv artifacts/ml/notebook-venv
$notebookPython = '.\artifacts\ml\notebook-venv\Scripts\python.exe'
& $notebookPython -m pip install -r src/Services/RepairPrediction/notebooks/requirements.txt
& $notebookPython -m jupyterlab
```

У JupyterLab відкрий ноутбуки з `src/Services/RepairPrediction/notebooks` та обери **Run → Run All Cells**. У VS Code або PyCharm можна відкрити ті самі файли, вибравши Python із цього середовища як kernel.

Типовий вхід — `artifacts/ml/repair-orders.csv`. Для іншого CSV з тією ж структурою зміни `DATA_PATH` у першій комірці коду. Ноутбуки використовують функції формування ознак і хронологічного поділу з проєкту. AppHost, Docker і база даних не потрібні. CSV та `.joblib` сайту не змінюються.
